# 問題の監査手順

問題の品質は、作った本人とは別の解答者に、正解を伏せて解かせることで確かめる。作問者と検証者が同じだと、同じ見落としが両方に残るからである。解答者には系統の異なる 2 種類のモデル（例：GPT 系と Claude Sonnet）を使い、両方が同じ指摘をした問題を優先して直す。

## 手順

1. `content lint` で形の不備（選択肢の形の不一致、重複した問題文など）を除く。
2. `content blind -out <dir>` で、正解・解説を除き選択肢を並べ替えた問題セットと、正解表（key.json）を書き出す。正解表は解答者が読めない場所に移す。
3. 2 系統の解答者に解かせ、問題ごとに次を出させる。解いた選択肢、ほかに成り立つ選択肢（別解）、語法だけで外せる誤答、各誤答のもっともらしさ（0〜2）、英文の自然さ。
4. 正解表と照合する。解答者が正解と違う選択肢を選んだ問題と、2 系統がそろって別解を挙げた問題は必ず直す。片方だけの指摘は読んで判断する。
5. 正解・解説・訳語の正しさは、`content review -out <dir>` で書き出した査読用データ（正解つき）を別の査読者に見せて確かめる。
6. 直した問題だけを、もう一度 3〜4 で解かせる。

誤答を「もっともらしく」する修正は、行き過ぎると別解を生む。そのため、差し替えた問題は必ず 6 で解き直す。
